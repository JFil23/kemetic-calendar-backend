# Credential retirement preparation — November 11, 2026

The canonical backend checkout and main branch remain the only source and
release authority. No branch, repository or worktree is created by this work.

`function_baselines/20261111` is immutable evidence captured from the deployed
Supabase functions. It is test/recovery data for a one-time credential migration,
not a feature-development folder. All 42 exports were compared against fresh
Management API multipart exports and every file matched. The manifest records
version, bundle identity and per-file SHA-256. This reconciles the previously
unrecorded personalization source without replacing its scoring with newer
canonical behavior. The two already-hardened reflection functions were captured
from their verified exact-source deployment receipt and confirmed live too.

`credential_cutover.py` builds uploads from those exact bytes, substituting only
API-key readers through the existing shared owner. The reviewed user/staff
handlers already validate sessions with Auth.getUser; their gateway can move off
the legacy-only verifier. The public astronomy computation receives an explicit
publishable-key/user verifier before that gateway change. Its calculation stays
unchanged. Every dependency remains included. SDK versions 2.27.0, 2.39.3 and
2.45.1 each passed a live zero-row privileged HEAD request with the opaque key.

Eight unavailable deployment records return NOT_FOUND_FUNCTION_BLOB. The ninth,
resolve_share, times out and its dashboard cannot load source. The app still
references resolve_share. Its broken canonical implementation referred to the
removed ma_at_flows table and recipient_email/accepted_at fields. The repair uses
the existing flow_shares.payload_json snapshot, a verified user, recipient/sender
ownership and the user's RLS client. It never reconstructs private source data or
marks a share accepted merely by viewing it. Unit tests and the existing local
real-database sharing round trip cover permitted and unrelated accounts and prove
that a preview changes no acknowledgement or payload. Unclaimed public-link
redemption is not enabled by this repair; copied tokens cannot bypass ownership.

A deployment requires the complete exact-source backend and admin gates. Preserve
the default opaque keys, cron secrets, schedules, callback identity, RLS and app
assets. Verify legitimate and forged-session boundaries before changing signing.
Import the legacy signing key, rotate to a new asymmetric key and preserve valid
old sessions for the configured lifetime plus the documented 15-minute margin
(75 minutes at the current one-hour lifetime). Only then disable legacy API keys
and revoke old signing trust. Verify denial of the exposed token as both API key
and bearer while new sessions, refreshes, service calls and app flows work.
Never re-enable the exposed key as routine rollback.

This preparation is not evidence that retirement has happened. Deployment and
per-service verification receipts belong in .git/deployment-receipts. The live
version.json remains the application deployment authority. App source, visual
references and persisted keys are unchanged by this backend migration.

Owner MFA is not enrolled in the connected Supabase account. Enrolling a factor
requires a device/recovery method controlled by the owner; this migration must
not silently enroll an agent-owned factor. The encrypted recovery archive and
public certificate were uploaded to iCloud and verified previously. Independent
recovery of the private key without this Mac remains unverified.
